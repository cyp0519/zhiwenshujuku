# 智问数据库 — 错误报告与修正分析

> 记录项目开发与调试过程中发现的所有错误、原因分析及最终解决方案

---

## 1. 虚拟环境重建与 Python 3.13 兼容性

**现象：** 执行 `start.bat` 后前后端均无法启动，`.venv` 目录为空。

**原因：**
- 原虚拟环境内容丢失（可能由项目迁移或路径变更导致）
- Python 3.13 下旧版编译 wheel（`.pyd`）不兼容，报模块缺失错误

**涉及的模块错误：**

| 模块 | 错误信息 | 原因 |
|------|----------|------|
| `pydantic_core._pydantic_core` | ModuleNotFoundError | 旧 wheel 为 Python 3.11 编译 |
| `uuid_utils._uuid_utils` | ModuleNotFoundError | uuid-utils 旧版无 3.13 wheel |
| `ormsgpack.ormsgpack` | ModuleNotFoundError | ormsgpack 旧版无 3.13 wheel |
| `numpy._core._multiarray_umath` | ModuleNotFoundError | 缓存了 cp311 的 `.pyd` 文件 |

**解决方案：**
1. 删除整个 `.venv`，执行 `python -m venv .venv` 重建
2. 将 `requirements.txt` 中所有 `==` 改为 `>=`，拉取 Python 3.13 原生 wheel
3. 最终成功安装 108 个包，后端健康检查通过

## 2. requirements.txt 编码错误

**现象：** `pip install` 时报 GBK 解码错误，依赖安装中断。

**原因：** `requirements.txt` 首行包含中文注释 `# 智问数据库 — 依赖清单`，pip 在 Windows GBK 环境下无法解码 UTF-8 中文字符。

**修复：**
- 移除首行中文注释，`requirements.txt` 从第 1 行开始直接写依赖包名
- 涉及文件：`zhiwenshujuku/requirements.txt`

## 3. 前端侧边栏重复导航项

**现象：** 侧边栏中多出 "app"、"SQL编辑器"、"对话查询"、"数据可视化"、"查询历史"、"系统概览" 等几行，点击无内容，与下方自定义导航按钮重复。

**原因：** Streamlit 自动扫描主入口文件同级目录下的 `pages/` 文件夹，将其中的 `.py` 文件识别为多页面应用的页面，并在侧边栏自动生成导航菜单。项目同时使用了自定义导航按钮 + 默认 Streamlit 页面发现，导致两组导航同时出现。

**修复：**
1. 将目录 `frontend/pages/` 重命名为 `frontend/views/`
2. 更新 `app.py` 中的 import 路径：`from frontend.pages.*` → `from frontend.views.*`
3. Streamlit 不再将 `views/` 识别为页面目录，自动导航消失

**涉及文件：**
- `frontend/app.py`（import 路径修改）
- `frontend/pages/` → `frontend/views/`（目录重命名）

## 4. 数据可视化 — Plotly `bar()` 参数错误

**现象：**
```
TypeError: bar() got an unexpected keyword argument 'margin'
```
堆栈指向 `数据可视化.py:55` 的 `_render_chart` 函数调用 `px.bar(df, **kwargs)`。

**原因：** `_render_chart` 函数通过 `**kwargs` 将所有参数同时传给 `px.bar()` 和 `fig.update_layout()`。`margin` 是 Plotly 的布局参数（layout parameter），只能用在 `update_layout()` 中，`px.bar()` 不接受此参数。

**修复：** 重构 `_render_chart` 函数，在传参给 `px.*` 之前，将布局参数（`height`、`margin`、`font`、`template`）从 kwargs 中弹出，仅传给 `fig.update_layout()`：

```python
def _render_chart(df, chart_type, **kwargs):
    layout_keys = ("height", "margin", "font", "template")
    layout_kwargs = {k: kwargs.pop(k) for k in layout_keys if k in kwargs}
    # ... create chart with remaining kwargs ...
    fig.update_layout(**layout_kwargs)
```

**涉及文件：** `frontend/views/数据可视化.py`

## 5. 示例问题点击无法触发 AI

**现象：** 在对话查询页面的 "你可以这样问" 区域，点击示例问题按钮后仅显示用户消息气泡，不会自动向 AI 发送请求并获取回复。

**原因：** 按钮的点击回调只执行了 `st.session_state.chat_messages.append(("user", ex))` 将消息追加到历史，然后 `st.rerun()`。但 AI 对话处理逻辑仅在 `st.chat_input` 有输入时触发，按钮事件未连接到此处理流程。

**修复：** 引入 `_pending_input` 队列机制：
1. 按钮点击时设置 `st.session_state._pending_input = ex`
2. 在输入处理段增加 `st.session_state.pop("_pending_input", None)` 检测
3. 检测到待处理输入时自动调用 `chat()` 函数

```python
# 按钮点击处
st.session_state._pending_input = ex

# 输入处理处
pending = st.session_state.pop("_pending_input", None)
if user_input or pending:
    prompt = user_input or pending
    # ... 调用 chat(prompt, ...) ...
```

**涉及文件：** `frontend/views/对话查询.py`

## 6. 侧边栏配色与对比度问题

**现象：** 深蓝渐变的侧边栏背景与白字搭配，在浅色工作区中显得突兀，部分文字/分隔线颜色使用 `rgba(255,255,255,*)` 硬编码，与新主题不匹配。

**修复过程（两次迭代）：**

| 元素 | 修改前 | 修改后 |
|------|--------|--------|
| 侧边栏背景 | `#1E3A5F → #152B45` 深蓝渐变 | `#E8F4FD → #D0E8F7` 浅蓝渐变 |
| 侧边栏文字 | `color: white` | `color: #1E3A5F` |
| 侧边栏标题 | `color: white` | `color: #1E3A5F` |
| 侧边栏副标题 | `rgba(255,255,255,0.7)` | `rgba(30,58,95,0.7)` |
| 侧边栏页脚 | `rgba(255,255,255,0.5)` | `rgba(30,58,95,0.5)` |
| 标题分隔线 | `rgba(255,255,255,0.1)` | `rgba(30,58,95,0.1)` |
| 内容分隔线 | `rgba(255,255,255,0.1)` | `rgba(30,58,95,0.12)` |

**涉及文件：** `frontend/styles.py`、`frontend/app.py`

## 7. 前端渲染性能瓶颈

**现象：** 整个前端使用起来"一卡一卡"，点击任何按钮后加载时间都很长。

**根本原因分析：**

| # | 瓶颈点 | 详情 |
|---|--------|------|
| 1 | 侧边栏每次 rerun 调 API | `app.py` 每次渲染调用 `get_health()` + `get_insights()`，无缓存 |
| 2 | `/insights` 端点慢 | 后端每次请求打开 6 个 SQLite 连接（6 条 `COUNT` 查询各开各关） |
| 3 | 系统概览无缓存 | `_render_query_stats` 和 `_render_er_diagram` 每次 tab 切换重新请求 |
| 4 | 数据可视化重请求 | 图表数据虽有缓存但 TTL 设置偏短 |

**修复措施：**

**a) 后端 `/insights` 优化**（6 连接 → 1 连接）：
```python
# 改前：6 次 execute_query()，每次新建连接
result["total_movies"] = db.execute_query("SELECT COUNT(*) ...").get("data", [{}])[0].get("cnt", 0)
# ... 重复 6 次

# 改后：1 个连接执行 6 条 SQL
conn = db.get_connection()
cursor = conn.cursor()
total_movies = cursor.execute("SELECT COUNT(*) as cnt FROM movies").fetchone()["cnt"]
# ... 共用同一个 cursor
conn.close()
```

**b) 前端缓存层**：
- `utils.py` 新增 `@st.cache_data(ttl=60)` 的 `_cached_get()` 函数
- `get_insights()` 和 `get_health()` 统一走缓存
- 系统概览 `_render_query_stats` 加 `@st.cache_data(ttl=120)`
- 系统概览 `_render_er_diagram` 加 `@st.cache_data(ttl=300)`

**涉及文件：**
- `backend/api.py`
- `frontend/utils.py`
- `frontend/app.py`
- `frontend/views/系统概览.py`

## 8. ER 图 TypeError 解包错误

**现象：**
```
TypeError: cannot unpack non-iterable float object
```
堆栈指向 `系统概览.py:280` → `_, src_half_h = _box_half_size(src, tables)`

**原因：** `_box_half_size()` 函数返回单个 `float` 值（框的半高），但调用处错误地使用元组解包语法 `_, var =` 尝试接收两个值。

**修复：** 将解包语法改为直接赋值：
```python
# 改前
_, src_half_h = _box_half_size(src, tables)
_, dst_half_h = _box_half_size(dst, tables)

# 改后
src_half_h = _box_half_size(src, tables)
dst_half_h = _box_half_size(dst, tables)
```

**涉及文件：** `frontend/views/系统概览.py`

## 9. Streamlit 空 label 警告

**现象：**
```
WARNING: `label` got an empty value. This is discouraged for accessibility reasons
and may be disallowed in the future by raising an exception.
```
堆栈指向 `SQL编辑器.py:99` → `st.selectbox("", [...], label_visibility="collapsed")`

**原因：** `st.selectbox("", ...)` 的第一个参数（label）传入了空字符串 `""`。Streamlit 新版本要求所有 widget 必须有非空的 label 值以满足无障碍访问标准（a11y）。

**修复：** 将空字符串替换为有意义的 label 名称，配合 `label_visibility="collapsed"` 保持视觉隐藏：
```python
# 改前
selected = st.selectbox("", ["快速示例..."] + sample_queries, label_visibility="collapsed")

# 改后
selected = st.selectbox("快速示例", ["快速示例..."] + sample_queries, label_visibility="collapsed")
```

**涉及文件：** `frontend/views/SQL编辑器.py`
