## 二、Phase 1：架构修复

### 2.1 前端路由重构 — 删除 exec()

**问题描述：** 原始代码使用 `exec(open(...).read())` 动态执行页面文件，存在代码注入风险，无法被 IDE 正确解析和调试，且违反 Python 最佳实践。

**优化方案：** 将每个页面文件封装为 `page()` 函数，`app.py` 通过函数调用实现页面路由，同时提取共享样式到 `frontend/styles.py`。

| 对比项      | 优化前                                                             | 优化后                                                                 |
| -------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| **路由机制** | `exec(open("frontend/pages/对话查询.py", encoding="utf-8").read())` | `from frontend.pages.对话查询 import page as chat_page` → `chat_page()` |
| **安全性**  | 动态执行任意代码，存在注入风险                                                 | 静态导入，Python 模块系统保障安全                                                |
| **可调试性** | IDE 无法追踪 exec 内部代码                                              | 完整的代码补全和断点调试支持                                                      |
| **代码复用** | 每个页面重复定义 CSS 和样式                                                | 共享 `styles.py` 模块，`page_header()` 组件复用                              |

**优化前代码（app.py）：**

```python
# 危险：动态执行页面文件
page = st.session_state.page
if page == "chat":
    exec(open("frontend/pages/对话查询.py", encoding="utf-8").read())
elif page == "sql":
    exec(open("frontend/pages/SQL编辑器.py", encoding="utf-8").read())
elif page == "viz":
    exec(open("frontend/pages/数据可视化.py", encoding="utf-8").read())
elif page == "history":
    exec(open("frontend/pages/查询历史.py", encoding="utf-8").read())
```

**优化后代码（app.py）：**

```python

from frontend.pages.SQL编辑器 import page as sql_page
```

### 2.2 SQL 编辑器安全校验

**问题描述：** 对话流程中的 SQL 执行有安全校验节点，但 `/sql/execute` API 端点直接执行用户提交的 SQL，完全绕过安全检查，可执行 `DROP`、`DELETE` 等危险操作。

| 对比项      | 优化前                       | 优化后                             |
| -------- | ------------------------- | ------------------------------- |
| **安全检查** | `/sql/execute` 无任何校验，直接执行 | 执行前检查 DROP/DELETE/INSERT 等危险关键词 |
| **错误提示** | 直接暴露数据库错误详情               | 返回通用错误提示，内部错误记录到日志              |

**优化前代码（api.py）：**

```python
@app.post("/sql/execute", response_model=SQLExecuteResponse)
async def execute_sql(req: SQLExecuteRequest):
    try:
        if not req.sql.strip():
            raise HTTPException(status_code=400, detail="SQL 不能为空")
        # 危险：直接执行，无安全检查
        result = app_state.db.execute_query(req.sql)
        ...
```

**优化后代码（api.py）：**

```python
@app.post("/sql/execute", response_model=SQLExecuteResponse)
async def execute_sql(req: SQLExecuteRequest):
    try:
        if not req.sql.strip():
            raise HTTPException(status_code=400, detail="SQL 不能为空")

        # 安全校验 — 阻止危险 SQL 关键词
        found_unsafe = [
            kw for kw in UNSAFE_SQL_KEYWORDS
            if re.search(rf"\b{kw}\b", req.sql, re.IGNORECASE)
        ]
        if found_unsafe:
            raise HTTPException(
                status_code=403,
                detail=f"禁止执行包含危险关键词的 SQL: {', '.join(k.upper() for k in found_unsafe)}"
            )

        result = app_state.db.execute_query(req.sql)
        ...
```

### 2.4 异常处理规范化

**问题描述：** `nodes.py` 中存在裸 `except:` 语句，吞掉所有异常包括 `KeyboardInterrupt`；`api.py` 向客户端暴露完整 traceback 信息。

| 对比项              | 优化前                       | 优化后                                                              |
| ---------------- | ------------------------- | ---------------------------------------------------------------- |
| **nodes.py:121** | `except:` 吞掉所有异常          | `except (json.JSONDecodeError, TypeError, AttributeError):` 精确捕获 |
| **api.py 异常响应**  | `detail=str(e)` 泄露内部路径和堆栈 | `detail="服务器内部错误，请稍后重试"` 内部错误仅记录到日志                              |

**优化前代码（nodes.py）：**

```python
try:
    result = json.loads(response.content)
except json.JSONDecodeError:
    try:
        json_match = re.search(r'\{.*\}', response.content, re.DOTALL)
        if json_match:
            result = json.loads(json_match.group())
        else:
            result = {"sql_query": "", "sql_explanation": "无法生成 SQL"}
    except:  # 危险：裸 except，吞掉 KeyboardInterrupt 等
        result = {"sql_query": "", "sql_explanation": "无法生成 SQL"}
```

**优化后代码（nodes.py）：**

```python
try:
    result = json.loads(response.content)
except (json.JSONDecodeError, TypeError):
    try:
        json_match = re.search(r'\{.*\}', response.content, re.DOTALL)
        if json_match:
            result = json.loads(json_match.group())
        else:
            result = {"sql_query": "", "sql_explanation": "无法生成 SQL"}
    except (json.JSONDecodeError, TypeError, AttributeError):  # 精确异常类型
        result = {"sql_query": "", "sql_explanation": "无法生成 SQL"}
```

### 3.2 可视化页面并行加载

数据可视化页面原本串行执行 6 个 SQL 查询，改为使用 `ThreadPoolExecutor` 并行执行，配合 `@st.cache_data(ttl=60)` 缓存，首次加载速度提升约 3-4 倍。

| 对比项             | 优化前                  | 优化后                                      |
| --------------- | -------------------- | ---------------------------------------- |
| **查询方式**        | `for` 循环串行执行         | `ThreadPoolExecutor(max_workers=6)` 并行执行 |
| **加载耗时 (6 查询)** | 约 600ms (串行 6×100ms) | 约 150ms (并行 max)                         |

**优化前代码：**

```python
@st.cache_data(ttl=60)
def _load_chart_data():
    charts = {}
    queries = { "rating_dist": "...", "yearly": "...", ... }
    for key, sql in queries.items():        # 串行：逐个执行
        result = execute_sql(sql)
        if result and result.get("success"):
            charts[key] = pd.DataFrame(result["data"])
    return charts
```

**优化后代码：**

```python
def _fetch_one(key: str, sql: str) -> tuple[str, pd.DataFrame | None]:
    result = execute_sql(sql)
    if result and result.get("success"):
        return key, pd.DataFrame(result["data"])
    return key, None

@st.cache_data(ttl=60)
def _load_chart_data():
    charts = {}
    with ThreadPoolExecutor(max_workers=6) as pool:  # 并行：同时执行
        futures = {
            pool.submit(_fetch_one, key, sql): key
            for key, sql in CHART_QUERIES.items()
        }
        for future in as_completed(futures):
            key, df = future.result()
            if df is not None and not df.empty:
                charts[key] = df
    return charts
```

```python
def _ensure_db(self):
    """确保数据库文件和表存在"""
    if not Path(self.db_path).exists():
        logger.warning(f"数据库文件不存在: {self.db_path}")
        return
    # 迁移：确保 is_favorite 列存在
    try:
        conn = self.get_connection()
        conn.execute("SELECT is_favorite FROM query_history LIMIT 1")
        conn.close()
    except sqlite3.OperationalError:
        logger.info("迁移: 添加 is_favorite 列到 query_history 表")
        conn = self.get_connection()
        conn.execute("ALTER TABLE query_history ADD COLUMN is_favorite INTEGER DEFAULT 0")
        conn.commit()
        conn.close()
```

### 7.1 CORS 跨域限制

**问题描述：** 原始配置 `allow_origins=["*"]` 完全开放跨域访问，任何网站都可以调用 API，存在安全风险。

### 7.2 SQL 注入防护增强

**问题描述：** 原始安全检查仅过滤危险关键词（DROP、DELETE 等），可被 SQL 注入技巧绕过，如：
- `SELECT * FROM movies /* DROP TABLE */` — 块注释绕过
- `SELECT * FROM movies -- WHERE 1=1` — 行注释绕过
- `SELECT * FROM movies; DROP TABLE users` — 分号分隔多语句

| 对比项 | 优化前 | 优化后 |
|--------|--------|--------|
| **检测范围** | 仅危险关键词 | 关键词 + 注入特征模式 |
| **可绕过性** | 可被注释、分号绕过 | 正则检测注释、分号、UNION 注入等 |
| **配置位置** | 仅 `config.py` | `config.py` 定义模式，`nodes.py` 和 `api.py` 双重检查 |

**新增注入特征模式（config.py）：**

```python
SQL_INJECTION_PATTERNS = [
    r"/\*.*?\*/",           # 块注释 /* ... */
    r"--\s*",               # 行注释 --
    r";\s*\w",              # 多语句分号
    r"union\s+select",      # UNION 注入
    r"into\s+outfile",      # 文件写入
    r"load_file\s*\(",      # 文件读取
    r"benchmark\s*\(",      # 时间盲注
    r"sleep\s*\(",          # 时间盲注
]
```

**安全校验节点增强（nodes.py）：**

```python
def sql_safety_validator(state: State) -> dict:
    sql = state.sql_query
    found_unsafe = []

    # 检查危险关键词
    for keyword in UNSAFE_SQL_KEYWORDS:
        if re.search(rf"\b{keyword}\b", sql, re.IGNORECASE):
            found_unsafe.append(keyword.upper())

    # 检查注入特征模式
    for pattern in SQL_INJECTION_PATTERNS:
        if re.search(pattern, sql, re.IGNORECASE | re.DOTALL):
            found_unsafe.append(f"注入特征: {pattern}")
            break

    if found_unsafe:
        return {"sql_safety_status": "unsafe", "messages": [AIMessage(content=f"❌ SQL 安全检查失败: {', '.join(found_unsafe)}")]}
    return {"sql_safety_status": "safe"}
```

### 7.4 LLM 实例复用

**问题描述：** 原始代码每次调用 `_get_llm()` 都创建新的 LLM 实例，造成不必要的开销。

| 对比项 | 优化前 | 优化后 |
|--------|--------|--------|
| **实例创建** | 每次调用创建新实例 | `@lru_cache` 缓存，最多 8 个实例 |
| **内存占用** | 持续增长 | 固定上限 |
| **初始化耗时** | 每次都执行 | 仅首次创建 |

**优化后代码（nodes.py）：**

```python
from functools import lru_cache

@lru_cache(maxsize=8)
def _get_cached_llm(model: str, temp: float, json_mode: bool):
    """缓存 LLM 实例，避免重复创建"""
    kwargs = dict(model=model, model_provider="openai", temperature=temp)
    if json_mode:
        kwargs["model_kwargs"] = {"response_format": {"type": "json_object"}}
    return init_chat_model(**kwargs)

def _get_llm(model: str = None, temp: float = 0, json_mode: bool = False):
    return _get_cached_llm(model or LLM_MODEL, temp, json_mode)
```

### 7.5 数据库连接优化

**问题描述：** 原始代码对所有 SQL 执行都调用 `conn.commit()`，即使是只读的 SELECT 查询，造成不必要的 I/O。

| 对比项 | 优化前 | 优化后 |
|--------|--------|--------|
| **commit 策略** | 所有查询都 commit | 仅写操作（INSERT/UPDATE/DELETE）commit |
| **性能影响** | SELECT 也有写 I/O | SELECT 纯读取，无额外开销 |

**优化后代码（database.py）：**

```python
def execute_query(self, sql: str) -> dict:
    ...
    cursor = conn.execute(sql)

    if cursor.description:
        columns = [desc[0] for desc in cursor.description]
        rows = cursor.fetchall()
        data = [dict(zip(columns, row)) for row in rows]
        result["data"] = data
        result["columns"] = columns
        result["row_count"] = len(data)

    # 仅在写操作时 commit
    sql_upper = sql.strip().upper()
    if any(sql_upper.startswith(kw) for kw in ("INSERT", "UPDATE", "DELETE", "ALTER", "CREATE", "DROP")):
        conn.commit()

    conn.close()
    ...
```
